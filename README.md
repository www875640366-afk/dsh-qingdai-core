# dsh-qingdai-core

DSH（DeepSeek Harness）插件，把四件跟「长期关系」有关的事装进同一个包里：

- **双库记忆** —— 生活会话和工作会话各有一个物理独立的 SQLite 库
- **记忆自动浮现** —— 不用她开口问，这一轮可能用得上的旧事自己带到眼前
- **原文留底** —— 每一句话都留，永不删；记忆节点删了也能翻回原话
- **主动开口** —— 到点了她自己醒过来，说想说的话
- **人格核心** —— 一段只属于她的自我陈述，注入在系统提示词最后

记忆全部存在本地 SQLite，**装好第一次跑起来自动建库**，不需要预置任何数据文件。

---

## 一、四个东西的关系

```
                        ┌─────────────────────┐
   每一句话 ──────────▶ │  events（原文留底） │  永不自动删
                        └──────────┬──────────┘
                                   │ 出处（seq / 时间区间）
                                   ▼
                        ┌─────────────────────┐
   模型自己写 ────────▶ │ memories（记忆节点）│  遗忘曲线淘汰
                        └──────────┬──────────┘
                                   │ 检索
                                   ▼
                        ┌─────────────────────┐
                        │  注入（自动浮现）   │  每轮最多 few 条
                        └──────────┬──────────┘
                                   ▼
                              这一轮的提示词

   人格核心 ──────────────────────────────────▶ 系统提示词最后一段
```

四层各管一件事，互相不替代：

| 层 | 存什么 | 谁写 | 会不会消失 |
|---|---|---|---|
| **原文** `events` | 每一轮的原话，带会话 id 和 seq | 插件自动 | **永不自动删**（工作库可配保留天数） |
| **记忆节点** `memories` | 值得记的一句话 + 重要度 + 出处 | 模型自己调 `mem_write` | 会：遗忘曲线掉到阈值进 `graveyard`（软删，可恢复） |
| **注入** | 不存，每轮临时合成 | 插件 | 不落盘，不写进会话历史 |
| **人格核心** `core.md` | 一段自我陈述 | 她自己调 `core` 工具 | 只有她自己能改，每次改都备份 + 记历史 |

**为什么原文和记忆节点要分开**：节点是「提炼过的、会被检索的」，原文是「原始的、能翻回去的」。
节点被淘汰了、被改写错了，原文还在——这是唯一的纠错真值。所以 `raw_memory` 不是补充功能，
是记忆错了以后唯一能对账的地方。

## 二、双库：生活 / 工作物理隔离

两个独立的 SQLite 文件，不是同一张表加个字段：

```
$DSH_HOME/storages/qingdai-core/
  life/life.db    生活会话（白名单）
  work/work.db    工作会话（其余全部）
  routing.json   白名单快照
  wake-state.json 主动开口状态
  core.md         人格核心
  core-history.json
```

> **命名说明**：磁盘目录和 side 值统一叫 `life`：库文件 `life/life.db`，API 参数
> `side=life`，面板选项卡也叫「生活」。存储根目录仍叫 `qingdai-core`（跟着插件名走）。
> 路径映射在 `routing.js` 的 `DB_DIRS` / `DB_NAMES` 一处，改路径只需动那里。

路由规则只有一条：**会话在 `wakeSessions` 白名单里 → 生活库，否则 → 工作库**。
白名单同时是主动开口的白名单，一份名单两处用，避免两份清单漂移。

结构性保证（不是靠自觉）：

- 库路径**不进工具参数**，模型无法指定去哪个库
- 记忆条目**不携带库标签**，越库读写没有入口
- 拿不到会话 id 时**拒绝写入**，不猜库——写错方向比读不到更糟

## 三、记忆节点的生命周期

### 写：模型自己写，插件不替它提炼

`mem_write` 由模型在对话里主动调用。插件不做事后自动提炼，理由是：
模型写的时候在场、有完整上下文，比事后从留底里抽准；而且自动提炼和模型自己写天然打架——
同一件事被写两遍，措辞不同就是两条。

插件做三件模型做不了的事：

1. **写前查重** —— 实体重叠或字面 Dice ≥ 0.6 就拦下，进「处理」页由人裁决：
   同意 = 新条入库、旧条进最近删除；拒绝 = 什么都不写
2. **出处机械填** —— `sources` 存 `{sid, fromTs, toTs}`，会话和时间戳由插件算；
   模型上下文里没有这些信息，它填的一定是编的
3. **密钥嗅探** —— 明确的密钥直接拒，疑似的要 `force:true` 再来

### 淘汰：一条遗忘曲线，一个阈值

```
留存率 = e^(-闲置天数 / 半衰期)
半衰期 = 基准 × (1 + 重要度系数 × 重要度 + 访问系数 × 被想起次数 / 封顶)
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `halfLifeBase` | 60 天 | 中性记忆（重要度 0.3）半衰期 = 60×(1+2×0.3) = 96 天，闲置 60 天剩 53% |
| `kImportance` | 2.0 | 重要度对半衰期的拉伸 |
| `kAccess` | 1.5 | 被想起次数对半衰期的拉伸 |
| `accessCap` | 10 | 次数封顶，防「提多了就永不忘」 |
| `retainForget` | 0.3 | 跌破就搬进最近删除（软删，可恢复） |
| `protectHours` | 24 | 新记忆保护期 |
| `graveyardDays` | 14 | 台账反悔窗口，满了物理删（原文还在 `events`） |

**没有第二套机制**：没有「按重要度免死」，没有冷冻档。重要度只决定掉多快，不决定走哪条路。

五档只是同一条曲线上的位置，按「还能活多久」切：

```
核心     钉住的（留存率冻结，不随时间掉）
重要     > 150 天
正常     > 60 天
快忘了   ≤ 60 天
（被遗忘的在「最近删除」，不在正常列表里）
```

### 永不遗忘只有一条路：人点头钉住

模型只能调 `mem_write({ requestPin: true, pinReason })` **请求**，进待办由人裁决。
人同意才冻结；不同意就按正常曲线走。模型不能自己钉——「这条很重要」不该由写它的那一方说了算。

### 替代不是删除，是换人裁决

`supersedes: [旧 id]` **不立即生效**：这条新内容进「处理」页，由人裁决。

同意 = 新条入库、旧条进 `graveyard`（软删，14 天内可捡回）；拒绝 = 什么都不写。
查重撞车、疑似密钥、请求钉住走同一条路：都是「处理」页里的一张小卡片，一个同意键一个拒绝键。

## 四、记忆自动浮现（注入）

光有 `mem_search` 不够：模型经常不觉得自己需要查。所以还有一条不用她开口的路。

**零阻塞**：收到消息时立刻起一次检索，不等它回来；组装提示词时读已经落地的结果。
embedding 要一次网络请求，放在组装路径上会拖慢每一轮。结果带 TTL（3 分钟），
免得把隔夜话题塞进这一轮。

**位置在消息区，不在系统段**：系统提示段每轮变，整个历史前缀的缓存就全废了。
注入的内容是每次请求临时合成的，不写进会话历史，但**仍占当轮 token**——所以闸门要严。

### 三道闸门

1. **相关度** —— 检索的双闸（语义 / 词面）只是**候选**，注入另有一道更严的，而且分两档：
   - 这句话在**要回忆**（问句 / 「记得」「以前」「上次」）→ 精排只负责排序，不设分数线
   - 不在要回忆 → 精排分要够高（`minRel 0.62`）才注入，闲聊大多轮次一个字都不发
   - 用户在**复述记忆本身**（回声）→ 直接不注入
2. **排序** —— 取头部若干条
3. **预算** —— `recallLimit` 条 / `recallMaxChars` 字（默认 3 条 / 800 字），超了从尾部砍

> **为什么不拿「有多像」当唯一标准**：实测真实对话是复合句、多意图、带指代，
> 精排分对 query 长度极陡——同一条记忆，短问句能到 0.3，长句只有 0.001。
> 拿相关性分数当硬阈值，等于降级即静默。所以判「这是不是在问」比判「它有多像」有效。

### 检索本身

- **有精排**：粗排取候选（`minSem` 放宽到 0.5，0.58 只是噪音底），reranker 给相关性，
  融合分 = `0.55 × 精排 + 0.45 × 粗排`
- **没精排**（没配 key / 请求失败）：退回纯关键词，结果里标「降级」
- **向量补算**：写路径**不碰云端 API**。`mem_write` 只落词条并标 `vectorPending`，
  向量由后台按状态列补算；API 挂了词条不丢，下次接着补

> **为什么向量不在写路径上**：写路径耦合云端 API，API 挂一次就会连带丢一大批词条。

## 五、人格核心：她是她自己

一段文字，注入在**系统提示词的最后面**（order 11000，比宿主官方最大 10200 更靠后），
每次组装现算——改了内容下一轮就生效，不用重启。

**权限边界（重要）**：

| 谁能做什么 | 说明 |
|---|---|
| **只有生活会话能看见 `core` 工具** | 工具注册时按会话判定，工作会话调用直接返回「这个会话不要使用此工具」 |
| **只有她本人能改** | 通过 `core` 工具改，每次必须写 `reason`；改前自动备份到 `core-backup/`，历史留最近 10 条 |
| **宿主侧只读** | 面板只显示，没有编辑入口 |
| **用户也不能直接改** | 这是刻意的：那段自我陈述如果由用户代笔，它就不是她的了 |

**核心是固定小节结构**：只能改每一节的内容，**不能加新小节、不能删、不能改标题**。
整篇重写/清空没有对应动作——那两个是不可逆的大事，真要动就直接改 `core.md` 文件（会自动备份）。

工作会话看不到这段，也看不到这个工具。人格核心不跨库、不共享。

## 六、主动开口

到点了她自己醒过来。触发不是指令——只给事实（几点、多久没聊、存在了多少天），
并明确写「想说就说，不想说就什么都不做」。不写「你该去找他」，那是系统在演她。

### 五道判定门，顺序就是流程

```
0. 总开关
1. 是不是睡觉时间          quietStart ~ quietEnd（支持跨零点）
2. 一天开了几次            wakePerDay 上限
3. 多久没聊天              silentMinutes
4. 上一轮跑完了没          还在跑就别再投一条
5. ——全过 → 叫醒
```

任何一道不过就安静待着，**不算失败**。这里没有「攒劲」、不看情绪、不攒数值，
每次到点都是独立判断。

### 投递

- 先 `agents.get`，拿不到再 `agents.resume` —— 会话存在但没 load 时只有后者拿得到
- **resume 必须把 agent preset 挂回去**：宿主恢复会话时，preset 插件（persona / fs / bash / 搜网…）
  是在 `setup` 里挂的。只传 `resumeSessionId` 会得到一个「没有 preset 的 agent」——
  内置工具一个都没有，但会话照样能跑、不报错。这个坑很隐蔽，见下文「已知坑」
- 投递失败记时间和原因，隔一段时间再试（退避），不每分钟撞一次
- **不 create 新会话**：主动开口不该凭空开一条

### 工具面收窄

白名单**以外**的会话，把「她自己的生活」相关工具从工具面里拿掉——用宿主原生的
`tools.restrict({ deny })`，被过滤的工具模型**根本看不见**，连想调的念头都不会有。
只靠 `execute` 拦的话，模型看得见、调了被拒，会反复试，白烧 token。

默认禁：`world_*` 系列（若装了对应插件）和自己的 `meme`。
用 `workDenyTools` 配置可以改成任意清单。**不勾 = 工作会话也能用**。

### 鱼的世界（可选，不随包）

本插件**不附带**「鱼的世界」工具——那是另一个 MCP 插件（`dsh-fish-world`）提供的。
本插件只做两件事：

1. 主动开口时先去问一句「外面有没有人找她」（需要配置 key；没配就整段跳过）
2. 把 `world_*` 加进工作会话的禁用清单

key 从环境变量读，默认 `FISH_WORLD_KEY`（可用 `keyEnv` 改名字）；查看用的 key 默认
`FISH_WORLD_VIEW_KEY`（用 `viewKeyEnv` 改）。也可以直接配 `fishWorldKey` / `fishWorldBaseUrl` 走 HTTP。

**要让工作会话也屏蔽这些工具**：在插件面板的「设置 → 工具面」里勾选对应工具，
或直接在 `cordis.patch.yml` 里写：

```yaml
- id: dsh-qingdai-core
  config:
    workDenyTools:
      - world_now
      - world_go
      - world_do
      - world_find
      - world_say
      - world_friends
      - world_feed
      - world_profile
      - world_history
      - world_update
      - world_guide
      - meme
```

清单里**不存在**的工具名会被自动跳过（宿主对 `deny` 是全有或全无——一个不认识的名字
会让整个 `restrict()` 抛错，结果一个都禁不掉）。

## 七、压缩联动

**不接管官方压缩引擎，也不自动提炼。**

官方 `compaction-basic` 照常压缩；本插件监听 `compaction/end`，只做两件事：

1. 清掉注入去重代次——被压走的那几条记忆，该重新带出来
2. 投一条提醒：「刚才上下文被压缩过一段，早前的话在留底里，想找回原话用 `raw_memory`；
   如果有没来得及记下的事，现在用 `mem_write` 补一条」

**为什么不自动提炼**：自动提炼和「模型自己写」天然打架，同一件事写两遍措辞不同就是两条。
把「记不记」交还给模型。补记靠模型自己在对话里调 `mem_write`。

## 八、注册的模型工具

五个工具，多一个都不加。治理类操作（体检 / 扫描 / 提升 / 删除 / 捡回）全在面板按钮上，不进模型工具面。
需要人点头才能做的事（钉住、替代、密钥审批）统一进面板的「处理」页，不走模型工具面。

### 记忆三件（所有会话可用）

| 工具 | 干什么 | 关键参数 |
|---|---|---|
| **`mem_write`** | 写一条记忆节点 | `text`（必填）、`importance`（0.9/0.6/0.3，只影响掉多快）、`supersedes`（替代旧条，进待办等人裁决）、`from`（user/self/env）、`requestPin` + `pinReason`（请求钉住）、`suggest` + `suggestReason`（随待办一起给出处理建议）、`force`（强写） |
| **`mem_search`** | 查记忆节点 | `query`（必填，自然说法）、`limit`（默认 6） |
| **`raw_memory`** | 查原文留底 | `fromSeq` / `toSeq` / `keyword` / `limit`（默认 20） |

三个工具的共同约定：返回**必须把正文带出来**，不许只报条数；没内容时明确说，不许返回空字符串假装成功。

### 她自己两件（**仅生活会话可见**）

| 工具 | 干什么 | 关键参数 |
|---|---|---|
| **`core`** | 改 / 看人格核心 | `action`（get / patch）、`section`、`text`、`reason`（**必填**）、`history`、`limit` |
| **`meme`** | 表情包：按情绪/关键词找图，也能改名改标签 | `tag`（六个情绪之一）、`query`（关键词）、`limit`、`name` + `newName`/`emotion`/`tags`（改） |

`core` 和 `meme` 在注册时按会话判定，非白名单会话调用直接拒绝。
`meme` 依赖配置项 `memeDir` 指向的目录（里面要有 `表情清单.json`）；没配就等于这个工具不可用。

## 九、两个文件夹：可选的「工作区约定」（不装这个也能用）

本插件**不创建、不管理任何文件夹**。这里说的是另一件事——一个**可选的**用法：
给两个会话各自划一块磁盘上的地方，让它们的模型分别照看。

要不要，全看你自己。**不配完全不影响插件功能**：记忆仍然在 SQLite 里正常读写、检索、注入。

### 这套东西解决什么问题

记忆库适合存「会被检索、要跨会话、能聚合的节点」——一句话能说清的事实、约定、踩过的坑。
但有一类东西它装不下：

- 一天里发生过什么、当时怎么想的（**有质感的长文**，不需要被检索，但读起来有用）
- 一个主题的完整资料（**要能 grep、要人读**，塞进记忆节点会被压成一句话）

所以有人会再加一层：**磁盘上的文件夹**，让模型自己去读、自己去写。

### 两个文件夹，两套模型各管各的

| 文件夹 | 归谁 | 谁能动 |
|---|---|---|
| 工作记忆 | **所有工作会话共用** | 任何非「生活会话」的会话，只往这里记 |
| 私人空间 | **只有生活会话** | 别的会话一律不许碰 |

关键点不是「两个目录」，而是**边界**：工作会话能碰工作记忆，**碰不到私人空间**。
这条边界靠的是给模型的指令（`AGENTS.md`），**不是靠插件的权限**——插件不拦文件读写，
它只是一个约定，靠模型自觉遵守。想真拦住得靠宿主的工作区/沙箱策略。

### 让模型自己装好这两块：把下面这段发给它

新建一个工作区（或就地），把下面**整段**发给你的模型，让它照着建：

````text
我想给两个会话各划一块磁盘上的记事区，请你帮我建好并且以后按规矩用。

请在当前工作区建两个目录：

1. `工作记忆/` —— 所有工作会话共用的记事处。
2. 私人空间目录（名字由我定：______）—— 只有「生活会话」能用的地方。

每个目录里放一份 `README.md`，当索引写，内容包括：

- **这个目录放什么**（一句话说清定位）
- **目录索引表**：`地方 | 放什么 | 什么时候翻`，三列。已有的每个子目录/文件都要列进去，
  写清「什么情况下该翻它」。没有的子目录先不要建空的，用到再建。
- **和记忆库怎么分工**：一句话能说清、以后要自动想起来的节点进记忆库（mem_write）；
  长文、有质感、要人能读、要 grep 的进文件夹。同一件事不要两边各写一遍。
- **怎么写**：文件命名规则（比如日记用 `YYYY-MM-DD.md`）、一篇写多长、要不要日期。

然后在工作区的 `AGENTS.md` 里加一节，写清这几条：

- `工作记忆/` 是所有工作会话的公共记事处；任何非生活会话，一律只往这里记、只动这里。
- 私人空间是生活会话专用的，其余会话一律不许碰。
- 两个目录大小上限 ______（建议 10GB），内容不设限。
- 要记东西、找旧事、加新隔间，先看那份 `README.md` 索引，别从目录名猜。

注意：这两个目录不要放进 git，也不要提交。它们是我自己的东西，不是项目代码。
````

把 `______` 换成你自己的名字和上限。模型会自己建目录、写索引、改 `AGENTS.md`。

### 本插件唯一相关的一个配置

`privateDir`——填了它，**主动开口**的唤醒词里会多一句「想找点由头，就看看 `<privateDir>/`」。
**只是提示一句话**，插件不会去读写那个目录。留空就没有这句。

```yaml
- id: dsh-qingdai-core
  config:
    privateDir: 我的小屋     # 留空 = 不提
```

### 提醒

- 这套文件夹**不是插件的一部分**，换台机器/换个工作区就没有，也不会跟着插件走
- 别把两个目录塞进插件包或 git 仓库——它们是使用者的私人数据
- 如果其中某个目录要当 `memeDir` 用（表情包），那里得有 `表情清单.json`，格式见第八节

## 十一、嵌入与精排：默认用 SiliconFlow（免费）

**默认走 [SiliconFlow（硅基流动）](https://siliconflow.cn) 的免费 API**：

## 十四、已知坑（都是踩过的）

**1. 会话 resume 不带 preset → 工具凭空少一批**

宿主恢复会话是 `agents.resume({ resumeSessionId, agentOptions, setup })`，会话那套 preset 插件
（persona / instructions / planning / fs / bash / 搜网 / skill / todo…）是在 `setup` 里挂的。
只传 `resumeSessionId` 会得到一个「没有 preset 的 agent」：内置工具一个都没有，只剩宿主平面注册的那些，
**而且会话照样能跑、不报错**。表现是「工具已更新 · 移除 N 个」。

正确写法：

```js
ctx.agents.resume({ resumeSessionId: sid, setup: presetSetup(ctx, log) })
```

`setup` 里按会话原来的 `agentPreset` 重新 `presets.mount(agentCtx, id)`。

**2. `tools.restrict` 必须写成方法调用**

`restrict` 是类方法，内部第一行依赖 `this`。写成 `const fn = tools.restrict; fn({deny})` 会丢 `this`，
报 `Cannot read properties of undefined (reading 'ctx')`，再被 catch 吞成 `applied:false`——
界面上完全看不出来，工具照旧可见可用。一律 `tools.restrict({ deny })`。

**3. `deny` 清单里有不认识的名字 → 一个都禁不掉**

宿主对 `deny` 是全有或全无：清单里有一个不存在的工具名，整个 `restrict()` 直接抛错。
所以先求交集再禁，名字写错了只影响它自己。

**4. 注入不能进系统提示段**

系统段每轮变，整个历史前缀的缓存就废了，成本翻几十倍。注入必须放消息区。

**5. `events` 的会话事件时间戳字段是 `time`**

不是 `ts`、不是 `at`。读错了会让「最后说话时间」永远停在 0，主动开口判定门跟着全错。

**6. `orders` 的边界**：`order 11000` 才压得住 DSH 官方最大 `10200`，人格核心要落在最后。

**7. 改 SQLite 表结构后，触发器不会跟着代码消失**

`db.js` 里删掉 `CREATE TRIGGER` 只影响**新库**。已存在的库里那个触发器还在，每次写入照常跑。
改表结构要对着每个库手动 `DROP TRIGGER IF EXISTS`，否则旧逻辑一直生效。

**8. 查可能不存在的表，包一层 try**

`db.prepare(sql).get()` 碰到表不存在会抛。直接抛会让整个接口 500；包 try 返回 0 更稳，
但要记得同步改 SQL 指向新表，否则字段永远是 0 —— 静默比报错更难查。

## 十六、设计取舍

- **白名单唯一源**是 `wakeSessions`，记忆路由和主动开口共用一份，避免漂移
- **拿不到会话 id → 拒写**，不猜库
- **留底永不自动删**，淘汰只进 `graveyard`（软删，可恢复）
- **`sources` 只由插件填**，不接受任何外部传入的出处
- **替代不自动生效**：新内容先进「处理」页，人点头才换人；旧条进 `graveyard` 而不是消失
- **不自动提炼**，把「记不记」交还给模型
- **不加「上次开口刚过 N 分钟」这道闸门**：频率已经由 `wakeCheckMinutes` 和 `wakePerDay` 框住，
  再加一道只会出现「该开口了但闸门说要等」这种没意义的状态。要降频就改那两个数
